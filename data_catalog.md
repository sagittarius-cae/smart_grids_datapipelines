# Smart grid & smart meter dataset — data catalog

Generated by `generate_smart_grid_dataset.py`. Files are numbered in dependency
order matching the ERD (top to bottom = generation source → transmission →
distribution → metering → data systems → consumers).

---

## 01_utility_providers.csv (5 rows)
The top-level owner/operator entity. Everything else in the dataset traces
back to one of these.

| Column | Type | Description |
|---|---|---|
| `provider_id` | string, PK | Unique utility identifier, e.g. `UP-0001` |
| `name` | string | Utility company name |
| `region` | string | Service territory / grid region |

---

## 02_power_plants.csv (50 rows)
Central generation assets owned by a utility.

| Column | Type | Description |
|---|---|---|
| `plant_id` | string, PK | Unique plant identifier, e.g. `PP-000001` |
| `provider_id` | string, FK → `01_utility_providers.provider_id` | Owning utility |
| `type` | string | Generation type: Coal, Natural Gas, Nuclear, Hydro, Solar Farm, Wind Farm |
| `capacity_mw` | float | Nameplate capacity in megawatts |

---

## 03_renewable_sources.csv (300 rows)
Distributed/utility-scale renewable generation feeding substations directly
(separate from large central plants).

| Column | Type | Description |
|---|---|---|
| `source_id` | string, PK | Unique identifier, e.g. `RS-000001` |
| `type` | string | Solar PV, Wind, Biomass, Small Hydro |
| `output_kw` | float | Rated output in kilowatts |

---

## 04_energy_storage.csv (150 rows)
Battery/storage assets that can feed a substation (charge/discharge).

| Column | Type | Description |
|---|---|---|
| `storage_id` | string, PK | Unique identifier, e.g. `ES-000001` |
| `type` | string | Li-ion BESS, Flow Battery, Flywheel |
| `capacity_kwh` | float | Usable energy capacity in kWh |

---

## 05_scada_dms.csv (10 rows)
Grid monitoring/control systems (SCADA = real-time telemetry & control;
DMS = Distribution Management System). Two per utility.

| Column | Type | Description |
|---|---|---|
| `system_id` | string, PK | Unique identifier, e.g. `SD-0001` |
| `provider_id` | string, FK → `01_utility_providers.provider_id` | Operating utility |
| `function` | string | `SCADA` or `DMS` |
| `control_center` | string | Name of the control center running this system |

---

## 06_substations.csv (2,000 rows)
Voltage transformation and switching hub. Each substation is fed by exactly
one upstream generation source (plant, renewable, or storage) and monitored
by one SCADA/DMS system.

| Column | Type | Description |
|---|---|---|
| `substation_id` | string, PK | Unique identifier, e.g. `SS-0000001` |
| `substation_type` | string | `Transmission` (step-up, near generation) or `Distribution` (step-down, toward feeders) |
| `location` | string | Synthetic zone/area label |
| `voltage_kv` | float | Nominal voltage in kV — transmission-class (115–500 kV) or distribution-class (4–34.5 kV) depending on `substation_type` |
| `source_type` | string | Which table `source_id` points to: `POWER_PLANT`, `RENEWABLE_SOURCE`, or `ENERGY_STORAGE` |
| `source_id` | string, FK → matching table per `source_type` | The upstream generation asset feeding this substation |
| `scada_id` | string, FK → `05_scada_dms.system_id` | Monitoring/control system for this substation |

---

## 07_power_transformers.csv (4,000 rows)
Substation-level power transformers (MVA-class), step down from
transmission to distribution voltage.

| Column | Type | Description |
|---|---|---|
| `transformer_id` | string, PK | Unique identifier, e.g. `PT-0000001` |
| `substation_id` | string, FK → `06_substations.substation_id` | Housing substation |
| `capacity_mva` | float | Rated capacity in MVA |

---

## 08_distribution_networks.csv (10,000 rows)
Distribution feeders leaving a substation.

| Column | Type | Description |
|---|---|---|
| `network_id` | string, PK | Unique identifier, e.g. `DN-0000001` |
| `substation_id` | string, FK → `06_substations.substation_id` | Originating substation |
| `feeder_type` | string | `Overhead` or `Underground` |
| `scada_id` | string, FK → `05_scada_dms.system_id` | Monitoring/control system for this feeder |

---

## 09_distribution_transformers.csv (500,000 rows)
Pole-mounted / pad-mounted transformers (kVA-class) that step feeder voltage
down to service voltage, right before the meter.

| Column | Type | Description |
|---|---|---|
| `transformer_id` | string, PK | Unique identifier, e.g. `DT-0000001` |
| `network_id` | string, FK → `08_distribution_networks.network_id` | Feeder this transformer sits on |
| `rated_kva` | int | Rated capacity in kVA (25/37.5/50/75/100/167/250) |

---

## 10_data_mgmt_systems.csv (5 rows)
Meter Data Management System (MDMS) — receives, validates, and stores
meter data for billing/analytics. One per utility.

| Column | Type | Description |
|---|---|---|
| `system_id` | string, PK | Unique identifier, e.g. `MD-0001` |
| `provider_id` | string, FK → `01_utility_providers.provider_id` | Owning utility |
| `storage_type` | string | `Cloud-Distributed` or `On-Prem Cluster` |
| `analytics_engine` | string | Analytics capability description (VEE = Validation, Estimation, Editing) |

---

## 11_ami_head_ends.csv (200 rows)
AMI Head-End System (HES) — manages the meter communication network
(RF mesh / cellular / PLC), collects readings, and forwards them to the MDMS.

| Column | Type | Description |
|---|---|---|
| `hes_id` | string, PK | Unique identifier, e.g. `HE-0001` |
| `network_type` | string | Communication network: `RF Mesh`, `Cellular (LTE-M)`, `PLC` |
| `coverage_area` | string | Synthetic label for the geographic area this head-end covers |
| `dms_system_id` | string, FK → `10_data_mgmt_systems.system_id` | MDMS this head-end forwards readings to |

---

## 12_consumers.csv.gz (10,000,000 rows)
End customers. Each consumer has exactly one smart meter (1:1).

| Column | Type | Description |
|---|---|---|
| `consumer_id` | string, PK | Unique identifier, e.g. `CN-00000001` |
| `account_type` | string | `Residential` (82%), `Commercial` (15%), `Industrial` (3%) |
| `address` | string | Synthetic street address |

---

## 13_smart_meters.csv.gz (10,000,000 rows)
The metering asset — the primary dataset. Sits at the end of the chain
because it references nearly every upstream entity.

| Column | Type | Description |
|---|---|---|
| `meter_id` | string, PK | Unique identifier, e.g. `SM-00000001` |
| `transformer_id` | string, FK → `09_distribution_transformers.transformer_id` | Distribution transformer serving this meter |
| `consumer_id` | string, FK → `12_consumers.consumer_id` | Consumer this meter belongs to (1:1) |
| `hes_id` | string, FK → `11_ami_head_ends.hes_id` | Head-end system this meter reports to |
| `install_date` | date (YYYY-MM-DD) | Date the meter was installed, 2015–2023 |
| `reading_date` | date (YYYY-MM-DD) | Date of the most recent reading snapshot, Jun–Jul 2026 |
| `comm_protocol` | string | Communication protocol: `RF_MESH` (60%), `CELLULAR` (25%), `PLC` (15%) |

---

## Referential integrity chain

```
utility_providers
  ├─ power_plants ─┐
  ├─ scada_dms      │
  └─ data_mgmt_systems ──> ami_head_ends
renewable_sources ──┤
energy_storage ──────┤
                      ▼
                 substations ──> power_transformers
                      │
                      ▼
              distribution_networks
                      │
                      ▼
            distribution_transformers
                      │
                      ▼
                smart_meters ◄── consumers (1:1)
                      │
                      └──> ami_head_ends
```

All foreign keys were populated by sampling directly from the parent
entity's ID array at generation time — every FK value in every file is
guaranteed to exist in its parent table (spot-checked on 2M+ meter rows,
zero orphaned references).
